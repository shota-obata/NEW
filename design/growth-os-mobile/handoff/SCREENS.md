## 0. 端末登録（未登録端末では、ここから先に進めません）

未登録の端末では、ログイン画面に到達しません。個人IDもPINも表示しません。

- **未登録**：セリフ見出し「この端末は、登録されていません。」→ 端末情報（機種／OS／端末の指紋／ネットワーク）を中立ボックスで提示 → **暖色ボックス**「4桁は、それだけでは弱い。」→ 塗りボタン「この端末を登録する」＋ゴーストボタン「登録コードをManagementに依頼する」。
- **依頼**：Managementの受信ボックスに届く内容（申請者／端末／場所／登録済み台数）をティールカードで提示。
- **1/3 コード**：6桁ドット（13×13px、gap 13px、PINドットと同じ挙動）＋キーパッド（高さ54px）。「残り15分で失効します」→ 揃うと「● 照合できます」。
- **2/3 所有**：端末名（ティール罫線の入力欄）＋2択ラジオ（個人の端末／店舗の共有端末）。共有を選ぶと暖色ボックス「共有端末では『裏』を開きません。」に切り替わる（無操作3分で自動サインアウト）。
- **3/3 完了**：ティールカードに登録内容（端末名／所有／登録日／有効期限）＋中立ボックス「この登録が残る先」3項目（本人の受信ボックス／Managementの端末一覧／監査ログ）→「PINでサインインする」。

## 0-3. 同意（`/consent`）

初回ログインの直後、および規定の版が上がったときに入ります。**同意しないと本体に入れません。抜け道は作りません。**

ヘッダー「同意 / 初回のみ · 第2版」。セリフ見出し23px「このアプリで記録されること」→ 本文13px / line-height 2.05。5項目をカードで縦に並べます（番号10.5px/700/.1em ＋ 見出し14px/660 ＋ 本文13px/2.05）。

1. 記録されるもの — 施術の記録、before/after 画像、相談と返答、到達の判断、操作履歴
2. 誰が見られるか — 可視領域8区分の要約
3. **指導内容の確認について** — **暖色カード**（背景 `#faf3ee` / 罫線 `#ecd9cd` / 文字 `#8a4d2e`）。文言はぼかさずそのまま出す（`POLICY_INTERNAL_RULES.md` §5 に全文）
4. 評価に直結しないこと
5. 退職後の扱い

下部固定：チェックボックス（20×20px / 角丸6px。未チェック `1.5px solid #c4beb4`、チェック時 `#2e6e75` 塗り＋白の✓、行はティール罫線に変化）「内容を確認しました」→ 塗りボタン「同意して開始」（チェックまで `#ddd8ce`＋`#8f8b84` の無効）→ ゴースト「規定の全文を読む」。

## 0-4. 規定の全文（`/policy`）

**全役割から到達できます** — Staffは「役割」画面、Support / Managementは「設定」の中。

版セグメント（第2版（現行）／第1版）→ 中立ボックスに版・施行・自分の同意日時 → 版が上がっていればティールカード「前の版から変わったところ」→ 全9条。条見出しは Georgia 15.5px＋（見出し）12.5px/640、項番は22px幅の左カラムに `#a8a29a` 11.5px、本文13px / line-height 2.05。**第6条だけ左に `3px solid #3f8e97` の縦罫**（この規定の焦点なので）。末尾に附則。

## 0-5. 変わったところだけ（`/policy` の差分・`14b`）

受信ボックスの「規定が第2版になりました」と、再同意のときの「変わったところだけ」から開きます。

ヘッダー「変わったところ / 第1版 → 第2版」。セリフ見出し「2か所です。」→ 変更カード（条名＋ティールのバッジ「第5項を追加」／条文をティールの縦罫 `3px solid #3f8e97` 付き白ボックスで引用／その下に11.5px `#8f8b84` でなぜ変えたか）→ 中立ボックス → フッター「全文を読む」＋ゴースト「戻る」。

**全文（`0-4`）側にも差分が出ます。** 現行版を見ているとき、変わった条の見出しに「この版で変更」バッジ、追加された項に背景 `#e7f1f2`・項番700・「追加」バッジ（`#2e6e75` 塗り／9.5px）。**旧版を選ぶと、その項はそもそも表示されません**（当時は存在しなかったため）。項番も繰り上がります。

## 0-2. ログイン（共通）

役割セグメント（Staff / Support / Management）→ **端末カード** → 鍵の入力欄 → 4桁PINドット → キーパッド → サインイン。

- 端末カード（ティール淡：背景 `#e7f1f2` / 罫線 `#d2e3e5` / 角丸14px）：キッカー「1つ目の鍵 · 端末」（10.5px/700/.1em/`#2f6a71`）＋「この端末 · 登録済み」（14px/640/`#28565c`）＋補足「未登録の端末は、この画面まで来ません。PINの入力欄も出しません。」（11.5px/1.65）。

- セグメント：背景 `#e6e2da` / padding 4px / 角丸13px。選択中 背景 `#faf9f7`＋`box-shadow: 0 1px 2px rgba(20,20,19,.08)`。
- 鍵の欄：役割で数が変わる（Staff 1＋PIN / Support 2＋PIN / Management 3＋PIN）。1欄 = ラベル（10.5px/700/.1em/`#a8a29a`）＋値（15px/620）、`padding:13px 16px`、角丸14px、背景 `#faf9f7`。
- PINドット：14×14px、4つ、gap 16px。入力済み `#2e6e75` 塗り、未入力 `1.5px solid #c4beb4`。直前の1つのみ `scale(1.15)`。
- キーパッド：3列グリッド gap 8px。数字キー 高さ58px / 角丸14px / 背景 `#faf9f7` / 罫線 `1px solid #e3dfd7` / 22px 500。「消去」「1つ消す」は枠なし `#8f8b84` 12.5px/640。
- サインイン：4桁揃うまで `#ddd8ce`＋`#8f8b84`（無効）、揃うと `#2e6e75`＋白。
- 役割ごとの説明文（12.5px/1.8/`#57544e`）と、Support/Managementには注意ボックス（暖色）で併用不可を明示。

**実装注意**：PIN入力は必ず関数型更新（前の値から積む）で。連打で1桁しか入らないバグの原因になります。

**実装注意（タップ領域）**：**本文中の単独ボタンは42px以上**、主要ボタン50–52px、キーパッド58px。**ナビ・セグメント・チップは36px以上**で構いません — iOSの44px指針は独立したタップ対象の話で、連続して並ぶものには当てはまらないためです。実測はナビ36px、セグメント40px、チップ37–38px。

**実装注意（ボタンのフォント）**：`<button>` は `font-family` / `font-size` / `font-weight` / `letter-spacing` / `line-height` / `color` を**親から継承しません**。指定を書き漏らすとUA既定（Arial・13.333px・letter-spacing normal）に落ちます。CSSで一度だけ塞いでください。

```css
button { font-family: inherit; font-size: inherit; font-weight: inherit;
         letter-spacing: inherit; line-height: inherit; color: inherit }
```

インラインで明示している箇所はそちらが勝つので、書き漏れだけが直ります。

### 時間外・定休日（`13d`）

同じPractice記録の画面が、時刻で3状態に変わります。セグメントは「月14:00 営業中 ／ 月20:40 時間外 ／ 火 定休日」。

- **営業時間内**：注記なし。「いま届くもの」に4項目とも「送ります／届きます」。
- **時間外**：中立ボックスに1行「時間外の入力は義務ではありません。（就業規則 第2条第3項）」→「いま届かないもの」は暖色カード。
- **定休日（火）**：**暖色ボックス**に「定休日です。この記録は本人希望の練習として残ります。…必要ペースの分母には数えません」→ 中立ボックス「必要ペース」（`1.0h ／ 週 1.5h（この記録は加算されません）`）→ 催促は「水曜 11:00 に回します」、練習提案は「定休日には出しません」。

記録の作成はどの状態でもブロックしません。
